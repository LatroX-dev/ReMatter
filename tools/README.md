# Tools

These scripts generate and check ReMatter 0.7.0's data and assets. Run them from the repository root with Python 3.11 or newer. Apart from the two sprite renderers, they use only the Python standard library.

## Checks

Each check leaves the files untouched and exits with an error when something differs:

```sh
python3 tools/generate_material_data.py --check
python3 tools/generate_workshop_materials.py --check
python3 tools/generate_visual_assets.py --check
python3 tools/generate_family_assets.py --check
python3 tools/generate_gui_assets.py --check
python3 tools/generate_bench_shapes.py --check
python3 tools/generate_module_assets.py --check
python3 tools/generate_cell_models.py --check
python3 tools/generate_cell_transfer_assets.py --check
python3 tools/generate_component_assets.py --check
python3 tools/generate_advanced_material_icons.py --check
python3 tools/generate_metallurgy_assets.py --check
python3 tools/generate_device_assets.py --check
python3 tools/generate_illustrated_icons.py --check
python3 tools/generate_research_data.py --check
python3 tools/generate_primal_assets.py --check
python3 tools/generate_progression_assets.py --check
python3 tools/generate_energy_assets.py --check
python3 tools/generate_player_guidance.py --check
python3 tools/check_assets.py
python3 tools/check_visual_style.py
python3 -m unittest discover -s integrations/reforging/tests -p 'test_*.py'
```

`./gradlew build` compiles the mod and runs the Java tests, including the data tests of the ReForging integration.

## Chemistry data

- `generate_material_data.py` writes every item profile, fluid profile, synthesis permission and gas permission under `src/main/resources/data/rematter/rematter/` from the reviewed catalogue in `data/material_catalogue.json`. It also writes `docs/material-coverage.csv` and fills `docs/material-coverage.md` from `data/material_coverage_template.md`. Generation removes chemistry files that the catalogue does not produce, and it rejects batch energies above the limit it reads from the machine sources. `--check` compares instead of writing; `--catalogue` reads another catalogue file.
- `generate_workshop_materials.py` writes the preparation-only plain and coloured Matrix Crystals, the preparation and sintering recipes of the metal dusts, alloys, gem powders and advanced components, the smelting and blasting recipes of the dusts and alloy powders, the Sinter Furnace recipe, their recipe-book advancements, the dust and ingot tags, industrial direct and reclaim recipes, Precision-gated Primal Crystal and Discovery Lens preparation, the native empty-Hand-Preparator upgrade, and the optional Oritech, Mekanism and Ender IO recipes. The fraction, Matrix Blend and machine recipes are written by hand. Generated ReMatter preparation times apply `PRODUCTION_TIME_FACTOR = 4`; catalogue and hand-authored JSON durations are already final work ticks. Foreign machine timings keep their native values. `--check` compares instead of writing.
- `generate_research_data.py` writes exact material-research families from the reviewed catalogue and an explicit Discovery tier/dimension list. It never infers family membership or synthesis permission from tags, recipes or elemental similarity. `--check` compares without writing.
- `generate_player_guidance.py` writes ten optional advancement definitions. Their `minecraft:impossible` criteria are awarded only by matching server success hooks; an inventory pickup cannot stand in for a completed research or conversion operation. `--check` compares without writing.
- `inventory_materials.py` reads installed mod JARs from `--mods` and writes an evidence report to `--output` for manual review. It never creates profiles; keep its report outside the repository.

## Models and textures

- `generate_gui_assets.py` writes eight pixel-aligned console frames with GUI nine-slice metadata, the progress arrow and 91 icons from `UiPalette.java`. Neutral surfaces match the machine casing. One sprite vocabulary covers controls, status lamps and empty slots; Java supplies the device or resource tint. `--check` compares without writing; `--list` lists shipped drawings and alternatives. `RESEARCH_ICON` selects the Research tab drawing and `RESERVE` retains optional drawings without shipping unused sprites.
- `generate_family_assets.py` writes everything the Matter Drive, Matter Terminal, Network Interface, Machine Port, the three Matter Cables, Reactor Casing, Reactor Glass, both industrial controllers, the Chemical Reactor and the six workshop benches (Analyzer, Decomposer, Material Synthesizer, Material Preparator, Hand Preparator and Sinter Furnace) show: their sprites, block models, block states and item definitions. A model is a short list of boxes on a half-pixel grid. The generator writes only the faces that can be seen, gives faces on the block boundary a cullface, and maps every sprite at two texels per pixel: 32 x 32 for a block face, 16 x 16 for small parts. Lights, screens and showpieces are lit without ambient occlusion, so they keep their brightness when the machine stands between other blocks. The item of a machine shows it switched on, so the icons of the family differ by their device colour. It fails when boxes leave the grid, form slivers, intersect or would z-fight in any state the block can show, when a model exceeds its box budget, and when a sprite or model is referenced but not written. The faceplates and status lights of mounted cells are sprites only; the block entity renderer draws them. The Chemical Reactor has two reaction columns with animated active sight windows, generated from `reactor_showpiece.py`. The six benches share its open alcove chassis; `bench_showpieces.py` defines the scan plate, crusher, growth tray, grinding/mixing station, hand crank and oven. The inventory crank has the same resting bounds as its renderer, and a conservative swept envelope is checked against the complete housing. Connector seats, hubs and flanges use a separate dark metal palette; coloured rings continue to show side roles. The closed sides of a device belong to its port plates: the body leaves those faces out, and the checks run with every side blank and with every side connected. `--check` compares instead of writing.
- `port_plates.py` is the shared module of the port plates, used by the family, progression and energy generators. A side of a device is one block model chosen by its role: the plain casing face for a side without a connection, the painted seat and a ring half a pixel proud of it for a connection, in the Machine Port sprite of that role. It writes the plate models of both casings (`port_side_*`, `port_plate_*`, `port_plain_*`, `port_reactor_*`; the family generator owns the files) and the block state entry of the type `rematter:port_plates` that lists them per side and role. Which sides can be a connection is decided by `PortSides.java`; the module mirrors that table for the default look of the item and reads its one switch, `SEALED_TOP`, from the Java source, so `--check` of the three generators fails until the assets follow a changed switch. A Java test compares every block state with the table.
- `generate_visual_assets.py` writes only the palette-controlled sprites for moving renderer effects: the existing neutral white 16-pixel tint mask, shared by entity effects and the block atlas. Static hardware belongs to the family and module generators. Moving hardware samples their block sprites; geometry lights tint the mask with UiPalette colours. Generation removes the exact six retired block-effect hues, shared-material sprites and old machine tiles; `--check` reports those files instead of deleting them.
- `renderer_parts.py` owns the model-pixel coordinates of renderer hardware and generates `client/anim/RendererParts.java`. It checks twenty compositions at rest and at stroke ends against the baked chassis and mechanisms, including standing and suspended modules. The family generator invokes it; `--check` compares without writing.
- `work_sprites.py` paints the sixteen-frame interpolated work strips for the family, modules, generators and Energy Cubes from the same palettes. `REACTOR_LIQUID` in `reactor_showpiece.py` selects moving geometry (recommended) or the baked liquid-level alternative. Client `MachineRenderer.WAITING_LIGHT`, `INDUSTRIAL_FIELD` and `SCAN_HEAD` select the waiting lamp, chamber field and scanner alternatives.
- `generate_module_assets.py` writes the sprites, block models, block states and item definitions of the five industrial modules, and their loot tables, recipes, recipe-book advancements and block tag. A module has at most twelve boxes on the half-pixel grid: a common mount, a two-pixel socket plate with a gunmetal flange, and a mechanism whose silhouette tells its job. Its crystal and the tab on its mount have the hue of the Matrix Crystal in its recipe; `MODULE_HUE_PRESET` in `hardware_sprites.py` selects the assignment and sets the sprites and the crystal of the five recipes together. The working parts are separate models, swapped for lit ones while the module works; the item shows the module at work. The ceiling variant mirrors the floor design, with its sprites mapped again. Generation rejects family geometry errors and removes stale owned sprites and models. `--models-only` and `--textures-only` limit it to one part, and `--check` compares instead of writing.
- `generate_illustrated_icons.py` writes the opaque Ice Matrix Crystal, the Matrix Cluster and the Pressure Module and Parallel Upgrade illustrations as SVGs under `artwork/components/`, then renders them at 128 pixels. `UPGRADE_LOOK` switches between material inserts (recommended) and neutral graphite. The Matrix Cluster is built from the gem of the painted Matrix Crystals: the four clear crystals of its recipe, opaque, inside the same dark contour and with the same facets and reflections. `MATRIX_CLUSTER_LOOK` selects how they are joined: grown from one root (recommended), bound by an iron band, or fused two by two around an iron node. `illustrated-rendered.json` records source and PNG checksums, so `--check` needs no CairoSVG and changed drawings need it only to render.
- `generate_device_assets.py` writes the Pressure Module and Parallel Upgrade item definitions, plus the Pressure Module crafting recipe and advancement. The Parallel Upgrade recipe belongs exclusively to `generate_workshop_materials.py` and requires Industrial Preparation. Removed specialist devices are not generated or registered.
- `generate_primal_assets.py` writes the three explicit-dimension Primal Ores, their equal-value Silk Touch/shard loot, the Primal Shard, Primal Crystal and Discovery Lens icons, the Entangled Link assets, and the Primal Cell and Link recipes with their recipe-book advancements. An ore is three boxes of the same size, like the vanilla grass block: the host stone, which is the vanilla texture referenced at run time, a socket layer lit by the world, and an animated crystal layer at full brightness. `ORE_DESIGN` selects one of the crystal drawings in `ORE_DESIGNS`, and `PRIMAL_LOOK` how much of the Primal spectrum the crystals show. The icons are SVG drawings in `artwork/primal/`; rendering a changed drawing needs CairoSVG, and `artwork/primal/rendered.json` ties every sprite to its drawing by checksum, so `--check` runs without it. The Primal Cell items belong to `generate_cell_models.py`. Cell recipes start with fresh housings and never consume an existing filled cell. End placement excludes a 1,040-block radius, including a margin beyond the central island. `--check` compares without writing.
- `generate_energy_assets.py` writes the three Energy Cube tiers with four identical casing sides and centered connector seats around a recessed Ember energy core, plus independent crafting recipes, loot and recipe-book advancements. Each recipe supplies its tier's Matter Cable, whose exact stripe colours the casing and port band; a separate Ember identity plate remains visible even at zero charge. `ENERGY_CUBE_LOOK` switches between the recessed core (recommended), closed capacitor cabinet and cartridge rack. `ENERGY_PORT_STYLE` selects compact 6 px, trimmed 7 px or balanced 8 px seats (recommended) around the native 6 px cable flange. Facing, nine charge levels and the server's coarse `none`/`in`/`out` flow choose a shared housing and one charge part. Charging and discharging use reversed sixteen-frame Ember bands; a steady cube keeps the static sprite, with an empty core on the ordinary item. The seat of each of the four sides is a part of its own that exists while the side is a connection; top and bottom wear the same seat flush on the casing and show plain casing when disabled. No tier recipe consumes an older cube. `--check` compares instead of writing.
- `generate_progression_assets.py` builds the Primal Converter and both Crystal Generator fronts with the shared 32-pixel family palette and geometry checks. It also writes their crafting recipes and recipe-book advancements, plus the nine exact crystal-fuel definitions: 1,024 FE each standalone, disabled in the ReForging integration. The conservative own-recipe audit gives clay, furnace fuel and coloured additives zero cost; only the sand contribution and the full 25% FE-policy discount count toward the 50% energy-return ceiling. This does not establish the safety of external renewable-material or fuel paths. `--check` compares without writing.
- `generate_metallurgy_assets.py` writes only the nine metallurgy item model/definition pairs. The Sinter Furnace model and states belong exclusively to `generate_family_assets.py`.
- `generate_cell_transfer_assets.py` writes the unpowered six-bay Cell Transfer Station as twelve family-grid boxes, with three source bays on the left and three target bays on the right and no FE/network connector. Its exact Mint identity follows the Mint Matrix Crystal in the independent recipe, which consumes an empty housing rather than a filled Cell. `CONSOLE_LOOK` selects Twin3Bay Console (recommended), a continuous rail or separate recessed panels. Item and world show empty hardware; actual contents remain in the server and menu. The generator also owns the recipe, loot and recipe-book advancement. `--check` compares without writing.
- `generate_cell_models.py` writes the cartridge items of the Cell Housing, Matter Cells and Primal Cells: their item models, item definitions and cartridge sprites. The cartridge front is the faceplate sprite the Matter Drive draws in a bay, at the mounted size, with its status light in the same position, driven by the `rematter:cell_status` item property. A window in the body shows the crystal of the cell crafting recipe, read from `data/rematter/recipe/`, so run this after the generators that write those recipes. Primal cartridges and mounted fronts share the animated Primal rail and a separate static Violet window where their recipes include Violet. The same generator writes the server-safe `PrimalVisualColors` constants for the item usage bars from `family_palette.py`. `--check` compares instead of writing.
- `generate_component_assets.py` writes the item models of the component sprites and the Cell models, and checks that the sprites are 128-pixel RGBA images.
- `generate_advanced_material_icons.py` writes the item models of the crystal, powder, blend and advanced component sprites and checks their size.
- `generate_technical_sprites.py` and `generate_storage_sprites.py` draw the component, upgrade, pattern, rack, recovery parcel and guide icons as SVG files in `artwork/components/` and render them to `textures/item/`. They need [CairoSVG](https://cairosvg.org/) (`pip install cairosvg`), which needs the Cairo library.
- `check_assets.py` fails when a PNG under `src/main/resources/assets` carries chunks that are not needed to decode it, such as color profiles, resolution, background or text metadata. `--strip` removes them in place without touching the pixel data. The renderers above strip these chunks themselves.
- `check_visual_style.py` checks the shipped assets against the [visual style guide](../docs/visual-style.md): the size of every texture by asset class, the palette of block and GUI sprites, the form of item icons, block-style items for mounted hardware, the half-pixel grid and texel density of models, animation metadata (at least sixteen interpolated frames for glows, liquids and energy; only the red fault blink and the named Primal signature use hard steps), the vanilla host, light, animation and spectrum of the ores, colour literals in client code, and textures or models that nothing uses or that are missing. It reads the recipes for the colour rule: the result of a recipe shows the exact hue of every coloured Matrix Crystal in it, nothing shows a crystal hue without the crystal in its recipe chain, and the crystal table of the guide, `FAMILY`, and `machineAccent` in `UiPalette.java` agree with the recipes. It also compares the palette tables of the guide with the palette modules, and the port table of the guide with the block states: a disabled side is the plain face, a ring has the Machine Port sprite of its role, the ring colours of `MachinePortMode.java` are `PORT_MODES`, and no body model draws a face that belongs to its port plates. It uses only the standard library and writes nothing. Each finding names the rule and the fix; `--list` prints the texture inventory, `--hues` prints which crystal every recipe result holds and how many texels of each hue it shows, `--json FILE` writes the findings, and `--selftest` runs the rules against synthetic cases. Its `EXCEPTIONS` table holds the documented exceptions, each with a reason; an entry that no longer applies is reported.

`component_drawing.py`, `generated_files.py`, `machine_palette.py`, `recipe_discovery.py` and `material_tiles.py` are shared helpers of these generators. `recipe_discovery.py` builds exact ingredient-count discovery and recipe rewards for generated vanilla crafting recipes. `family_palette.py` holds the colours, `renderer_parts.py` the checked moving hardware, `work_sprites.py` the work-strip painters, `family_sprites.py` the pixel art and `family_geometry.py` the box, texture mapping and z-fighting checks. `hardware_sprites.py` holds the tile packer, painters, module hue assignments and animated Primal run shared by the hardware generators. The older bench housings in `artwork/machines/` remain artwork references; shipping bench geometry is defined by `bench_showpieces.py`. Module models are generated assets, and `data/material_catalogue.json` is the authored chemistry source. The original painted material icons are canonical PNG artwork recorded by checksum in `artwork/painted-icon-sources.json`; new or changed icons need an SVG or deterministic painter. The registry is a closed provenance exception, not an exception to the visual rules.
